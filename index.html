Cloud Computing and Security Issues


          
          

            
            

              
Most organisations don't buy their own hardware anymore. They rent storage, software
                and
                processing power and pay only for what they use. It's cheaper, and they can scale up or down whenever
                they need to. Even small businesses can now run on the same computing power as large ones without paying
                to build it.

            

          


          
The trade-off is control. Data that used to sit inside a company's own building now sits on
            infrastructure the company doesn't own and can't fully see. That's why the biggest objection to moving to
            the
            cloud isn't cost or speed. It's security.


          
> three logs available for inspection:


          
    
            
  • data_breach.log - what happens when shared storage is
              compromised
    • 
            
  • iam.log - who has access, and why that list goes stale
    • 
            
  • malware.log - how infected users bring down cloud services
    •

Data Breach


          
Data breaches rank among the most damaging security threats in cloud computing.


          
The Target attack shows the scale of exposure possible. Attackers entered through a
            third-party HVAC vendor, not Target's own systems, and exposed roughly 70 million customer records. The
            company paid close to $400 million in the aftermath.


          
The entry point matters more than people assume. Any vendor connected to a network
            becomes part of that network's attack surface, whether the organisation accounts for it or not.


          
> cloud platforms amplify the risk:


          
    
            
  • Large amounts of sensitive data sit together on shared servers
    • 
            
  • One successful breach can reach many customers at once
    • 
            
  • Data can leak during transfer, storage, audit or processing
    • 
            
  • Insiders with excess access are a threat alongside outside attackers
    • 
          


          
A single company losing a server room loses its own records. A compromised cloud
            platform can expose everyone on it. Moving data into the cloud multiplies the points where it can leak,
            and usually reduces how much of that movement an organisation can actually see.

Identity and Access Management


          
Weak identity and access management lets unauthorised actors into cloud systems, often
            without triggering any alarm.


          
> access control failures fall into four categories:


          
    
            
  • Account and service hijacking
    • 
            
  • Malicious insiders
    • 
            
  • Weak authentication
    • 
            
  • Poor handling of privileged accounts
    • 
          


          
A stolen password grants an attacker the exact same access as the real employee. The
            system doesn't flag the intrusion, because it reads the attacker as a normal user. Confidentiality,
            integrity and availability all fail at once.


          
Phishing remains the most common route to stolen credentials. The weakness sits with
            people, not technology, which is an uncomfortable finding for organisations that assume more security
            tools will fix the problem.


          
There's a second issue specific to the cloud. Infrastructure changes fast, so access
            controls set up once quickly go stale. Shared multi-tenant resources make it worse, letting properly
            authenticated users reach data they were never meant to see.


          
Access management isn't a one-time setup. It needs continuous attention.

Malware and Ransomware


          
Cloud infrastructure and the end users who depend on it are both increasingly targeted
            by malware and ransomware.


          
Spark, a New Zealand telecommunications provider, lost service in September 2014.
            Attackers installed malware on end-user devices and used them to launch a denial-of-service attack
            against Spark's cloud services. Spark denied any fault in its own architecture and blamed the infected
            user devices instead.


          
Information security is a continuous race, not a fixed target. As attackers improve
            their techniques, organisations need matching effort from security managers, IT specialists and ordinary
            staff, not just one department.


          
> the typical risk profile includes:


          
    
            
  • Data abuse
    • 
            
  • Malicious insiders
    • 
            
  • Insecure interfaces and access points
    • 
            
  • Shared technology weaknesses
    • 
            
  • Data loss and account hijacking
    • 
          


          
Malware rarely acts alone. It usually exploits a weak account or a careless user first,
            which ties this issue straight back to the other two.

Summary


          
All three problems trace back to the same source. Cloud computing works by sharing
            resources, and sharing means giving up part of the control an organisation used to have on its own
            premises.


          
data_breach.log - sensitive data from many
            customers sits on the same infrastructure, so one breach can reach all of them. The entry point is often
            a third party nobody was watching.


          
iam.log - a stolen credential turns an
            attacker into a legitimate user, and cloud infrastructure changes faster than most access lists get
            reviewed.


          
malware.log - malware finds the weak accounts
            and careless users the first two problems leave behind, then uses them to reach the infrastructure.


          
None of these has a permanent fix. Each depends on decisions that have to be made
            continuously, not once, and attackers adapt faster than most security policies get reviewed.
            Organisations that treat security as a box to tick when signing a contract usually pay for it later in
            money, reputation and disruption.


          
If you want to see one of these play out in real life, I linked a video about the Target
            data breach on the data breach page, or you can watch it directly on
            YouTube.
